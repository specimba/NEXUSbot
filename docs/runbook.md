# NEXUS OS — Runbook

## §0 Panel access (READ THIS FIRST)

**Your panel password lives in the `.env` file** at the project root (top level of the
workspace download), in the line:

```
PANEL_PASSWORD=<stored-in-.env-never-commit>
```

- **Where**: `.env` is a hidden dot-file next to `package.json`. It is gitignored and its
  value is never shown in chat, logs, or git history (directive P7 — by design).
- **How to view**: download the workspace, open `.env` with any text editor, read the
  `PANEL_PASSWORD=` line. Store it in your own password manager — the sandbox can be
  cold-reset by the platform, and you should own the value, not the sandbox.
- **How to change (rotation)**: two options.
  1. Ask the orchestrator: *"rotate panel password"* → it runs
     `bash scripts/rotate-panel-password.sh`, you re-download the workspace and read the
     new value from `.env`.
  2. If you ever run commands yourself: `bash scripts/rotate-panel-password.sh`.
- **After rotation** the dev server picks up the new value (Next.js dev hot-reloads
  `.env`); if in doubt, restart the dev server.
- **Other keys in `.env`** (all auto-generated by `scripts/ensure-env.sh`, all safe to
  rotate): `SESSION_SECRET` (cookie signing), `ENCRYPTION_KEY` (secrets vault AES-256-GCM).
  Rotating `ENCRYPTION_KEY` without `ENCRYPTION_KEYS_PREV` makes previously stored
  connector credentials unreadable — don't do it casually.

> Why did `.env` once look "empty"? The sandbox platform rewrites `.env` to
> `DATABASE_URL`-only on every cold boot (`/start.sh`). The project now self-heals:
> `.zscripts/dev.sh` runs `scripts/ensure-env.sh` at boot, which regenerates any missing
> key in-place. If the panel password disappears after a sandbox reset, it means the
> reset happened outside this mechanism — re-run ensure-env and rotate.

## §3 Secrets doctrine (P7)

- Secret **values** never enter: code, logs, git, chat, docs. Not even once.
- Connector credentials are stored via the panel (Connectors tab) into the encrypted
  vault (`src/lib/crypto.ts`, AES-256-GCM versioned envelope) — never into `.env`.
- Ingest tokens are stored as sha256 hashes; plaintext shown once at creation.
- The panel password is the one deliberate exception stored in `.env` — because the
  owner must be able to read it without the panel (bootstrap-of-bootstrap problem),
  and `.env` is gitignored + mounted-out of restores.
