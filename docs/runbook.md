# NEXUS OS — Runbook

## §0 Panel access (READ THIS FIRST)

**The panel password is stored DURABLY in the panel database** (Setting
`panel.passwordHash`, sha-256) — it **survives sandbox cold resets** even though
the platform regenerates the `.env` file on every boot.

- **Why this exists**: on 2026-10-25 the sandbox reset regenerated `.env` with a
  fresh random `PANEL_PASSWORD` and the owner was locked out ("Wrong panel
  password" loop). Since v29.12 the login check accepts TWO channels:
    1. the durable DB hash (primary — survives resets), and
    2. the `.env` `PANEL_PASSWORD` (recovery channel; the orchestrator can read
       it from the project root when the DB is also gone).
- **First successful login with the recovery password seeds the DB hash
  automatically** — after that, resets cannot lock you out again.
- **Rotation**: Settings → "Panel access" (current + new + repeat). Rotation
  writes the durable DB hash; the `.env` value keeps working as recovery unless
  you also rotate `.env` (scripts/rotate-panel-password.sh).
- **If BOTH channels are ever lost** (fresh DB + fresh .env): ask the
  orchestrator to run `scripts/ensure-env.sh`, read the printed hint, log in,
  and immediately set your own password in Settings → Panel access.
- **Other keys in `.env`** (auto-generated by `scripts/ensure-env.sh`):
  `SESSION_SECRET` (cookie signing), `ENCRYPTION_KEY` (secrets vault
  AES-256-GCM), `ENCRYPTION_KEYS_PREV` (optional legacy key list).
  ⚠ **Vault warning**: a sandbox reset rotates `ENCRYPTION_KEY`, which makes all
  stored connector credentials unreadable ("unknown vault keyId"). v29.12 added
  `scripts/reseed-vault-from-widget.ts` (re-arms hyperbrowser/upstash/vyce from
  the widget's stored keys) — the rest (Supabase PAT, db-url, GitHub, Webshare)
  must be re-entered by hand in Connectors. The Supabase Mgmt PAT is the
  critical one: without it, `Deploy cortex` (Connectors → Supabase) cannot ship
  edge updates. If the pre-reset DB ever needs restoring from the mirror, run
  `scripts/backfill-from-mirror.ts` AFTER re-entering `supabase-db-url`.

### Workspace download (Overview → Snapshot durability → "Download workspace")

- The **platform's own** workspace downloader ("Failed to archive workspace
  files") chokes on the full sandbox (~2.5 GB / 65k files incl. node_modules,
  .next, .git) — treat it as permanently unreliable.
- The **panel's button is the reliable path** (v29.15): it mints a ONE-TIME
  download link (single-use, 5 min) and always shows a fallback panel with a
  real "Save zip" anchor + a copyable URL. The URL downloads with **no cookie
  needed** — so it works even when the embedded preview iframe silently blocks
  file saves (the "button not responsive" report was the iframe eating the
  programmatic download; server logs showed the zip was built and served 200
  every time).
- If no file lands: click **"Open in New Tab"** above the preview and press the
  button there, or paste the copyable link into any browser tab.
- The zip = clean source + `RECOVERY.txt` (panel password + quick-start).
  Never contains `.env`, db, node_modules, upload/, or vault files.

## §3 Secrets doctrine (P7)

- Secret **values** never enter: code, logs, git, chat, docs. Not even once.
- Connector credentials are stored via the panel (Connectors tab) into the encrypted
  vault (`src/lib/crypto.ts`, AES-256-GCM versioned envelope) — never into `.env`.
- Ingest tokens are stored as sha256 hashes; plaintext shown once at creation.
- The panel password is the one deliberate exception stored in `.env` — because the
  owner must be able to read it without the panel (bootstrap-of-bootstrap problem),
  and `.env` is gitignored + mounted-out of restores.

## Supabase unlock (L0 mirror) — CURRENT dashboard route (updated 2026-07)

> The old "Project Settings → Database → Connection string" path is gone from the
> Supabase dashboard. Use the Connect modal instead:

1. Supabase dashboard → your project → **Connect** button (top bar) → modal
   "Connect to your project" opens with tabs: Framework / Server / **Direct** / ORM / MCP.
2. Pick the **Direct** tab (Framework/Server/ORM/MCP are code-recipe views, not plain strings).
3. Set the selector to **Transaction pooler** — port **6543**, host
   `aws-0-<region>.pooler.supabase.com`, user `postgres.<project-ref>`.
   Transaction mode is the serverless-safe endpoint (no idle connections to babysit).
   Avoid Session pooler (5432) and the direct `db.<ref>.supabase.co` host.
4. Copy the `postgresql://…` URI → paste into the NEXUS OS panel → Connectors →
   Supabase card → **DB connection string · L0 mirror** → Save.
   Stored encrypted in the vault (service `supabase`, label `supabase-db-url`).
   The section is visible even before the Mgmt PAT is stored — it is independent.
5. Sanity checks: URI must start with `postgresql://` (the input validates and
   disables Save otherwise); badge flips MISSING → STORED `••••`.
